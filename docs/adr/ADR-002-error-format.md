# ADR-002: Формат ответов с ошибками

## Context

API должен возвращать ошибки в едином формате для облегчения обработки клиентскими приложениями

## Decision

Использовать структурированный формат ошибок с полями code и message:
```json
{"error": {"code": "тип_ошибки", "message": "описание"}}
```

## Alternatives

1. **Стандартные HTTP ошибки FastAPI**

## Consequences

**Положительные:**
- Единообразная обработка ошибок во всех клиентах

**Отрицательные:**
- Необходимость явно обрабатывать все типы исключений

## Security Impact

- Контролируемое раскрытие информации об ошибках
- Предотвращение утечки внутренних деталей системы

## Rollout Plan

1. Создать класс ApiError с кодами ошибок
2. Добавить exception handlers для всех типов ошибок
3. Обновить все эндпоинты на использование ApiError
